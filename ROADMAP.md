# KARUSELKA — план разработки

> Отдельный Blender-аддон быстрого турнтейбла. Вынесен из LAMPOCHKA v3.2
> (решение 2026-08-29, имя выбрано 2026-08-31). Дизайн утверждён юзером.
> Юзкейс: шоурилы моделей — «пресет света (LAMPOCHKA v3.1) + турнтейбл =
> шоурил за две минуты».

## Статус: v1.1.1 (2026-08-31) — правка Object Spin по юзеру

Spin-пустышка переименована в **KARUSELKA_Empty**; в режим Object парентится
**корень иерархии таргета** (walk по .parent до вершины): если у таргета есть
родитель — парентится он, таргет сохраняет своё место в иерархии. Кейфреймы
по-прежнему на пустышке. Remove Rig отвязывает корень, иерархия таргета
остаётся нетронутой. Тесты: моки 126/126 + live 0 failed (кейс «у таргета
уже есть родитель» покрыт в обоих прогонах).

## Статус: v1.1.0 (2026-08-31) — фичарелиз по правкам юзера

Запрос юзера (дословно): застраховаться от мусорного стейта; два режима
турнтейбла; камера не в упор; настройки камеры из панели. Реализация:
1. **Камера всегда с чистых дефолтов** (линза 50, DoF off, авто-клипы 1000:1,
   свежий датаблок). Галка **Keep Settings** — пересборка наследует линзу/DoF/
   клипы предыдущей камеры вместо дефолтов. Панель синхронизируется с камерой.
2. **Mode: Camera / Object** — орбита камеры (pivot + парентинг камеры) или
   вращение объекта (spin-empty в центре bbox, таргет парентится к нему с
   сохранением мировой трансформы, камера статична и не запарентена, Track To
   на spin). Remove Rig отвязывает таргет, трансформа сохраняется.
3. **Margin** (дефолт 2.5, было жёстко 1.5) — авто-радиус = габарит × Margin.
4. **Настройки камеры в панели**: Lens/DoF/Clip Start/Clip End с update-
   колбэком — правки применяются к камере рига сразу.
Плюс: Render предупреждает при отсутствии света в сцене; страховка от
протухшего указателя props.camera после чужих удалений. Тесты: моки 121/121
+ live 0 failed (включая spin-цикл и keep-семантику; уроки: float32-клипы
нельзя сравнивать ==, кватернионный double-cover в углах).

## Статус: v1.0.0 реализована (2026-08-31, коммит f5e8899)

**v1.0.3 (2026-08-31):** клипы строго 1000:1 — near = radius/100, far = radius×10
(глубинный буфер не деградирует на крошечных и огромных моделях).

**Кейс «камера активна, вьюпорт чёрный» (диагностирован по сокету 9876 в живой
сцене юзера):** риг полностью исправен (aim 1.0, raycast в модель, GL-рендер
показывал модель) — чёрным был сам вьюпорт: `region_3d.view_camera_offset =
(nan, nan)` + view_camera_zoom −17 → кадр камеры не рисуется, весь вьюпорт =
passepartout. Починено сбросом offset/zoom (не аддонское). «Karuselka Cam.002»
в аутлайнере — имя датаблока, не второй объект. Уроки — в памяти blender-addon-lessons.

**v1.0.2 хотфикс (2026-08-31):** «в камеру ничего не вижу» — Create Rig не делал
свою камеру активной: Numpad 0 и рендер смотрели через старую scene.camera.
Фикс: rig-камера становится scene.camera (прежняя запоминается, Remove Rig
возвращает); у созданной камеры клип-плоскости подбираются под радиус орбиты
(мелкая модель иначе ближе near-плоскости = пустой вид). Тесты: прицел камеры
(view −Z → pivot), scene.camera set/restore.

**v1.0.1 хотфикс (2026-08-31):** «камера создаётся в рандомном месте» — Create Rig
на кадре ≠ 1 ставил камеру на угол этого кадра (на 60-м — ровно за объектом).
Фикс: после создания рига оператор прыгает на кадр 1; плюс явный сброс
`matrix_parent_inverse` (в 5.2 сеттер парента сбрасывает сам, в 3.6–4.x — нет);
имя target в отчёте оператора. Диагностика: `tests/diag_random_cam.py`,
регресс-проверки в live_check.

Сделано по дизайну ниже. Сборка — `python build.py` (генерит legacy с bl_info
+ оба zip в `out/v<версия>/`, копирует README/LICENSE; версию читает из

## Дизайн v1.0.0 (утверждён)

### Панель
Суб-панель/вкладка **KARUSELKA** в N-панели, компактная:
- Target (объект; фолбэк на активный при создании рига)
- Camera (своя или создаётся `LM Karuselka Cam`... имя: `Karuselka Cam`)
- Frames — кадров на полный оборот (дефолт 120; fps берётся из сцены)
- Rounds — оборотов (дефолт 1.0, float)
- Radius — 0 = auto (габарит объекта × 1.5; линза 50 мм даёт запас в кадр)
- Height — высота камеры относительно центра объекта
- Dir — CW/CCW (знак угла)
- Output — путь рендера (дефолт `//turntable/`)
- Кнопки: **Create Rig** / **Remove Rig** / **Render Turntable**

### Риг — Create Rig делает ВСЁ сразу, включая кейфреймы
1. Pivot-empty `Karuselka Pivot` в центре bbox объекта (мировой центр)
2. Камера — child pivot'а, локальная точка (radius, 0, height);
   **Track To → pivot** (орбита от парентинга, прицел от констрейнта —
   вращения не дублируются)
3. Кейфреймы `rotation_euler.z` на pivot'е: кадр 1 → 0°, кадр N →
   ±360° × Rounds; интерполяция **ПРИНУДИТЕЛЬНО LINEAR** (безье = непостоянная
   скорость — главная классическая ошибка турнтейблов)
4. Маркер `karuselka = 1` (custom prop) на всём своём — Remove Rig удаляет
   ТОЛЬКО своё: pivot, свою камеру, констрейнт со своей камеры, анимацию
5. DoF у созданной камеры выключен, линза 50 мм

### Рендер
- Render Turntable: frame_start=1, frame_end=Frames×Rounds, render.filepath,
  затем `bpy.ops.render.render('INVOKE_DEFAULT', animation=True)` —
  неблокирующе
- Настройки движка/сэмплов/формата НЕ трогаются
- Диапазон кадров сцены меняется только в момент рендера и остаётся
  видимым в таймлайне
- Repeat: повторный Create Rig обновляет существующий риг, не плодит
  (один риг за раз)

### Семантика подтверждена юзером
- Create Rig = риг + кейфреймы немедленно; таймлайн скрабится — камера
  уже облетает, ничего нажимать больше не надо
- Render Turntable ничего не создаёт

## Операторы и структура кода
- `karuselka.create_rig`, `karuselka.remove_rig`, `karuselka.render_turntable`
- PropertyGroup `Scene.karuselka` (target, camera, frames, rounds, radius,
  height, direction, output, статус рига через self["key"]-паттерн)
- Иконки сверять с enum Blender 5.x (урок LAMPOCHKA: 'ROTATE' не существует)

## Мок-тесты (~40 проверок)
- регистрация классов/указателей
- расчёт центра bbox и авто-радиуса
- число кейфреймов и линейность интерполяции
- знак направления, Rounds-множитель угла
- cleanup удаляет только своё (маркер), чужую камеру не трогает
- грабли мока из LAMPOCHKA: `remove(o, do_unlink=True)` kwarg,
  location-вектор с .x/.y, сокеты с живым is_linked

## Грабли, известные заранее (из LAMPOCHKA)
- `context.depsgraph` в модалках/операторах не существует →
  `context.evaluated_depsgraph_get()`
- Иконки — только из enum 5.x
- Extension: bl_info в legacy обязателен (в LAMPOCHKA v2.4.1/2.5.0 ушла
  регрессия — не повторять, legacy собирается скриптом с bl_info)
- Диагностика от юзера — через System Console сразу
